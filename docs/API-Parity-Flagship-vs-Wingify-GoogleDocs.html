6. Suggested bridge pseudocode (sendHit → trackEvent)

// Conceptual mapping for FlagshipWingify
func sendHitToWingify(_ event: FSEvent, visitor: FSVisitor) {
    let context = WingifyContextMapper.makeContext(from: visitor)
    var props: [String: Any] = [:]
    if let label = event.label { props["label"] = label }
    if let value = event.eventValue { props["value"] = value }
    // event.action is the Wingify event name
    WingifyFme.trackEvent(
        eventName: event.eventAction,
        context: context,
        eventProperties: props.isEmpty ? nil : props
    )
}

Limitations to surface in logs/docs:

  • Event name must exist in Wingify project (feature/holdout).
  • No ACK to the app.
  • Does not replace ABTasty hit pipeline unless product chooses dual-send or Wingify-only for Wingify keys.

8. FAQ

Q: Can we fully match Flagship visitorExposed() on Wingify?

A: No. Wingify sends impressions as part of getFlag. The bridge should document this and avoid promising deferred exposure for Wingify flags.

Q: Is sendHit → trackEvent a clean map?

A: For FSEvent, yes (best fit). For Page/Screen/Transaction/Item, only via conventions in eventProperties.

Q: Why isn’t metadata mappable?

A: Public GetFlag does not expose campaign/variation identifiers comparable to FSFlagMetadata.

Q: What about consent?

A: Wingify has no consent API. Product must decide whether Flagship consent also suppresses Wingify trackEvent / prefetch.
